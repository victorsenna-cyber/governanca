
● Planejamento Completo — Blueprint Operacional de Qualificação Manual

  Entregando apenas o planejamento, conforme solicitado. Nenhum arquivo será criado
  nesta etapa.

  ---
  1. Visão Geral do Artefato

  Nome interno: Blueprint Operacional de Qualificação Manual — Instagram (Débora)
  Formato: index.html único, autocontido, sem dependências externas.
  Natureza: Página estática premium, leve, com microinterações em JavaScript puro.
  Função: Guia operacional de uso diário, consultável em menos de 2 minutos, com
  scripts copiáveis e tabela de decisão clara.
  Persona de uso: Débora, executando qualificação manual de seguidores do Instagram em
   15–20 min/dia.

  Não é CRM, não é dashboard analítico, não é formulário. É um mapa de decisão visual
  e operacional.

  ---
  2. Objetivo da Página

  Objetivo primário: Permitir que Débora, em qualquer momento do dia, abra a página e
  saiba exatamente o que fazer com um novo seguidor — classificar, abordar ou
  descartar — usando scripts prontos e critérios leves.

  Objetivos secundários:
  - Reduzir fadiga de decisão na qualificação.
  - Padronizar abordagens sem engessar.
  - Servir como documento vivo de referência (impressão/exportação opcional).
  - Comunicar visualmente uma operação madura e estratégica.

  Promessa central: Lead certo antes de volume. Decisão antes de ferramenta.

  ---
  3. Arquitetura de Informação

  Hierarquia de leitura (do topo ao rodapé, escaneável em ~90 segundos):

  [1] Hero — contexto + propósito
          ↓
  [2] Fluxo visual — 6 etapas horizontais
          ↓
  [3] Cockpit de status — chips/tags de estados possíveis
          ↓
  [4] Campos opcionais — qualificação leve, sem obrigatoriedade
          ↓
  [5] Scripts copiáveis — biblioteca por categoria
          ↓
  [6] Tabela de decisão — situação → classificação → ação
          ↓
  [7] Rotina diária — checklist de 15–20 min
          ↓
  [8] Resumo executivo — fechamento mental

  Navegação: menu fixo no topo (sticky) com âncoras para cada seção. Em mobile, vira
  um menu compacto horizontal scrollável.

  4. Seções da Página

  4.1 Hero / Cabeçalho

  - Título grande: "Blueprint Operacional de Qualificação"
  - Subtítulo: "Instagram · Uso manual · Decisão antes de ferramenta"
  - Microcopy de 2 linhas explicando o propósito.
  - Selo/badge sutil: "Para Débora · Uso diário"
  - Sem CTA agressivo. Apenas um link âncora "Ver fluxo →".

  4.2 Fluxo Simples

  - 6 cards horizontais (em desktop) / vertical em mobile:
  Novo seguidor → Análise rápida → Abordagem → Qualificação → Classificação → Próxima
  ação
  - Cada card com ícone minimalista (SVG inline), título curto, 1 linha de descrição.
  - Setas/conectores sutis entre cards.

  4.3 Cockpit de Status

  - Grid de chips/tags representando os 11 status sugeridos.
  - Cada chip com cor sutil diferenciada (mas dentro da paleta neutra).
  - Texto auxiliar: "Exemplos editáveis. Use o que fizer sentido."
  - Agrupamento visual em 3 colunas:
    - Início: Novo seguidor, Interagiu, Respondeu DM
    - Em andamento: Em qualificação, Call convidada, Call agendada
    - Desfecho: Lead quente, Nutrição, Produto de entrada, Anti-ICP, Sem resposta

  4.4 Campos Opcionais de Qualificação

  - 7 cards de campo, cada um com 3–4 opções clicáveis (chips internos).
  - Comportamento: clicar destaca visualmente (toggle), mas não salva nada permanente
  — apenas ajuda Débora a "pensar em voz alta" enquanto avalia um lead.
  - Headline da seção: "Campos opcionais — guias mentais, nunca obrigatórios."

  4.5 Scripts Copiáveis

  - Sistema de abas ou acordeão com 8 categorias.
  - Cada script em um card com:
    - Texto do script (3–5 linhas curtas)
    - Botão "Copiar" no canto superior direito
    - Feedback visual ao copiar (chip "Copiado ✓" que aparece e some)
  - 2–3 variações por categoria para Débora escolher tom.

  Categorias planejadas:
  1. Abertura
  2. Pergunta diagnóstica
  3. Aprofundamento da dor
  4. Prontidão
  5. Convite para conversa
  6. Nutrição
  7. Produto de entrada
  8. Encerramento sem avanço

  4.6 Tabela de Decisão

  - Matriz visual de 3 colunas: Situação · Classificação · Próxima ação
  - 4–6 linhas iniciais (os exemplos do briefing).
  - Classificação destacada com cor sutil por tipo (quente / nutrição / entrada /
  anti-ICP).
  - Cada linha tem hover sutil que destaca o caminho de decisão.

  4.7 Rotina Diária

  - Lista numerada de 6 passos.
  - Cada passo com tempo estimado ao lado (ex: "3 min").
  - Tempo total no topo: "≈ 15–20 minutos por dia".
  - Visual de checklist, mas sem checkboxes funcionais (não é app de tarefa).
  - Opção: ícone discreto de impressora ao lado para imprimir só esta seção.

  4.8 Resumo Executivo

  - Bloco final centralizado, tipografia maior, espaçamento generoso.
  - Frase-síntese: "O objetivo não é conversar com todo mundo. É identificar quem tem
  dor, prontidão e aderência."
  - Rodapé minimalista com data de versão e crédito sutil.

  13. Responsividade

  Breakpoints:
  - >= 1024px: layout pleno, 2–3 colunas onde fizer sentido.
  - 768–1023px: tablet — fluxo vira 2x3 grid, scripts em 1 coluna larga.
  - 480–767px: mobile largo — tudo em coluna única, nav scrollável horizontal.
  - < 480px: mobile estreito — reduz padding, ajusta tipografia (base 14px), botões
  maiores (44px alvo de toque).

  Princípios:
  - Mobile-first no CSS (estilos base = mobile, @media (min-width) para escalar).
  - Sem scroll horizontal exceto na nav compacta.
  - Todos os botões com alvo de toque mínimo 44x44px.
  - Tabela de decisão: em mobile, vira lista de cards verticais (uma decisão por
  card).

  14. Acessibilidade

  - HTML semântico (landmarks: <header>, <nav>, <main>, <footer>).
  - Contraste mínimo WCAG AA (verificar --text-muted no fundo off-white).
  - Foco visível (:focus-visible com outline --accent).

  - Toast com aria-live="polite".
  - Abas com role="tablist", role="tab", aria-selected.
  - Ordem de tabulação lógica.
  - prefers-reduced-motion: desabilitar animações para quem prefere.
  - Imagens/ícones SVG com <title> ou aria-hidden quando decorativos.

  15. Critérios de Aceite

  A entrega final será considerada aprovada se:

  - Tudo em um único index.html, sem dependências externas obrigatórias.
  - Página carrega instantaneamente, mesmo offline.
  - Leitura completa do conteúdo em menos de 2 minutos.
  - Todos os scripts têm botão de copiar funcional com feedback visual.
  - Campos opcionais comunicam claramente que são guias, não obrigações.
  - Tabela de decisão permite decidir a próxima ação em segundos.
  - Rotina diária cabe visualmente em uma tela (desktop).
  - Layout responsivo funciona em mobile sem scroll horizontal.
  - Estética white premium: sem cores berrantes, sem visual de planilha.
  - Microinterações sutis, nunca distrativas.
  - Acessível via teclado, com foco visível.
  - Imprime bem (todas seções visíveis, nav oculta).
  - Código interno organizado em camadas legíveis (mesmo sendo arquivo único).
  - Nenhum console error ao abrir no navegador.

  16. Ordem Recomendada de Implementação

  Sequência de menor risco para maior valor entregue cedo:

  1. Esqueleto HTML semântico completo com todas as seções vazias e âncoras.
  2. Tokens CSS (cores, tipografia, espaçamento, sombras, radius).
  3. Reset + base + tipografia global + container.
  4. Hero + Nav sticky (validar identidade visual cedo).
  5. Fluxo visual (Seção 2) — valida densidade e respiro.
